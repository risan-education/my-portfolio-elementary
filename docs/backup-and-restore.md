# 控えを取り、開けるか確かめる

- 作成日: 2026-09-26
- 更新日: 2026-09-26

進学・引き継ぎ・大きな編集の前と、ときどき決めた日に控えを取ります。本人が利用停止・削除を希望した情報は、[利用範囲の見直し](record-choices.md)に従い、復元で戻さないようにします。

## 普段の控え

1. 自分用Privateの Code → Download ZIP で現在のファイルを取得する。
2. 外部ストレージの写真・PDF・動画も別に控えを取る。
3. 他人が見られない保管先に、保存日入りの名前で置く。必要に応じて端末や保管先を暗号化する。
4. 「取得日・対象・含まれるもの・含まれないもの」を控える。

ZIPにはGit履歴全体は含まれません。外部リンク先の原本も自動では入りません。クラウド同期だけを控えとせず、誤削除に巻き込まれない別のコピーを持ちます。

## 復元の練習

本番のノートに上書きせず、新しいフォルダでZIPを展開します。最近の記録、古い記録、画像を一つずつ開き、文字化けや欠落、外部原本の所在を確認します。
確認日と結果を家庭内で控えます。GitHubへ戻す必要があれば、新しいPrivateで確かめてから切り替えます。公開設定を変える必要はありません。

## Gitの履歴も残す（詳しい方向け）

[GitHub公式のバックアップ手順](https://docs.github.com/en/repositories/archiving-a-github-repository/backing-up-a-repository)に従い、ローカルにミラーを取得します。次は説明用です。URLを本人用に置き換え、同名フォルダがない場所で実行します。

~~~powershell
git clone --mirror https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git portfolio-backup.git
~~~

Git LFSを実際に使っている場合は、ミラーのフォルダ内で git lfs fetch --all による取得も必要です。IssueなどGit外の情報や外部原本は別途保管します。
控えは履歴内の個人情報も含みます。認証情報は控えに書き込みません。

取得したミラーから、新しいフォルダに通常の作業用コピーを作り、履歴とファイルが開けることを確かめます。LFS利用時はLFSの実体も確認します。ローカルミラーからの複製は環境に応じて --no-hardlinks を使い、検証用コピーを控えと独立させます。
本番へのmirror pushや強制pushは復元の練習に使いません。GitHubへの復元が必要な場合は、まず新しい空のPrivateを使い、詳しい人と確認します。
