# はじめ方（保護者向け）

- 作成日: 2026-09-25
- 更新日: 2026-09-26

この教材は、**保護者がChatGPTに体験を伝え、内容を確認して、自分用のGitHubリポジトリへ保存する**使い方を基本にします。このページで、初期設定から最初の記録まで進められます。

## 最初にすることの流れ

1. **ChatGPTにGoogleアカウントで新規登録する。** すでにアカウントがあればログインします。
2. **ChatGPT Plusを契約する。** 月額20米ドル（約3,000円が目安）のプランです。
3. **パソコン（またはスマホ）にChatGPTアプリをインストールする。**
4. **保護者用のGitHubアカウントを作る。** すでにアカウントがあればログインします。
5. **ChatGPTに聞きながらGitHubへの接続を設定し、テンプレートを非公開で複製する。** 下の依頼文を送り、案内に沿って進めます。
6. **ChatGPTに話しかけて、ポートフォリオを作成・編集する。** 体験を伝え、内容を確認して保存します。

以下は主にWindows・Macでの操作を想定しています。GitHubのファイルを作成・更新できる機能は、アプリ・アカウント・接続の種類によって異なります。スマホも含め、手順5で対応状況を確認してください。

## 1. ChatGPTに登録・ログインする

[ChatGPT](https://chatgpt.com/)で保護者のアカウントに登録・ログインします。**Googleアカウントでの登録がおすすめです。** 登録画面で「Googleで続行」を選び、保護者のGoogleアカウントで進みます。すでにChatGPTのアカウントがある方は、これまで使っていた方法でログインしてください。

Googleアカウントを持っていない方は、[Googleアカウントを作る手順](github-basics.md)を参考に、先に保護者用のアカウントを用意します。

## 2. ChatGPT Plusを契約する

1. プラン変更画面で **Plus** を選びます。**月額20米ドル（日本円で約3,000円が目安）のプランです。** 入口が見つからない場合は[公式プラン案内](https://learn.chatgpt.com/docs/pricing)から進みます。
2. 料金・請求周期・条件を確認し、保護者本人が支払い手続きを完了します。

約3,000円は1米ドル＝150円で換算した目安です。為替・税・契約方法などで金額が変わるため、実際の請求額は契約画面で確認してください。料金の確認日: 2026-09-26。

**ChatGPT Plusの契約後、必ず手順5のGitHubへの接続設定を行ってください。** この手順のためにAPIキーを発行する必要はありません。

## 3. ChatGPTアプリをインストールする

パソコン（Windows・Mac）またはスマホに公式ChatGPTアプリをインストールし、Plusを契約した同じアカウントでログインします。

## 4. 保護者用のGitHubアカウントを作る

### GitHubを初めて使う方へ

GitHubは、文章や写真を変更履歴とともに保存できるサービスです。この教材では、保護者が管理する学びのノート置き場として使います。

**[「GitHubって何？ 登録とログインのしかた」を開く](github-basics.md)**

Googleアカウントの作成から、GoogleでのGitHub登録・次回のログインまで説明しています。初めての方は、先に登録とログインを済ませてください。

GitHubの利用は原則13歳以上です。小学生本人のアカウント作成や保護者のログイン情報の共有を前提にせず、保護者が自分のアカウントを操作します。
[GitHubの利用規約](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)を確認してください。

## 5. ChatGPTに聞きながら接続し、テンプレートを非公開で複製する

ChatGPTアプリで新しい会話を開き、次の文章をそのまま送ります。この段階では、配布元のテンプレートのURLを使います。

> このテンプレートを私のGitHubに非公開で複製し、ここから編集したいです。必要な設定から順番に教えてください。
>
> https://github.com/risan-education/my-portfolio-elementary

ChatGPTに聞かれたら、使っている端末（Windows・Mac・スマホなど）や、保護者のGitHubユーザー名を伝えます。

### 案内に沿って接続・複製を進める

1. ChatGPTの案内に沿って、GitHubへの接続を設定します。ログインやアクセス許可は保護者が行い、表示された権限を確認します。
2. 複製先は保護者のアカウント、名前は例えば `family-learning-notes`、公開範囲は **Private（非公開）** と伝えます。
3. ChatGPTが直接複製できる環境では、複製を依頼します。直接複製できない場合は、ChatGPTに聞きながらGitHub画面で操作します。下の補足にも手順があります。
4. 作成されたページを開き、保護者のアカウントの下にあり、**Private** と表示されていることを確認します。

案内された項目が見つからなければ、「今の画面には○○と表示されています。次はどうすればよいですか？」と聞きながら進めます。

### 自分用の場所を作る

1. 保護者自身のGitHubアカウントで[ログイン](https://github.com/login)します。Googleで登録した方は **Continue with Google** を選びます。
2. [配布元のトップページ](https://github.com/risan-education/my-portfolio-elementary)で **Use this template → Create a new repository** を選びます。「このひな形から、自分用の保存場所を作る」という操作です。
3. **Owner（所有者）**には保護者のアカウント、**Repository name（保存場所の名前）**には、例えば `family-learning-notes` と入力します。名前に子どもの本名や学校名を入れる必要はありません。
4. **Private（非公開）**を選びます。「Include all branches」はチェックせずに進みます。
5. **Create repository from template** で作成し、リポジトリ名のそばに **Private** と表示されることを確認します。

例えば、保護者のユーザー名が `learning-parent`、保存場所の名前が `family-learning-notes` なら、ページ上部には `learning-parent / family-learning-notes` と表示されます。これは説明用の架空の名前です。実際には自分のユーザー名が表示されます。

この**自分用のページ**をブラウザーのお気に入りに保存すると、次回から開きやすくなります。

複製したリポジトリには配布元の `LICENSE`（MIT）も含まれます。これは用紙と説明文の配布条件で、あなたが書き足す記録には及びません。削除しても、そのまま残しても構いません。

「Use this template」が表示されない場合は、ログイン済みか、配布元のトップページを開いているかを確認してください。公開リポジトリに実記録を書かず、自分用のPrivateリポジトリを作ってから記録を始めます。

### 複製した自分用リポジトリをChatGPTに伝える

作成したページのURLをコピーし、同じ会話に貼り付けます。

> 自分用の保存先は https://github.com/xxx/xxxx です。ここを編集できるようにしてください。

**xxxは保護者のGitHubユーザー名、xxxxは複製したリポジトリ名です。** 例えば `https://github.com/learning-parent/family-learning-notes` のような形になります。これは架空例なので、実際には作成したページのURLを使ってください。

新しく作ったリポジトリへのアクセス許可が必要な場合も、ChatGPTの案内に沿って設定します。対象を選べる場合は、そのリポジトリにアクセスを限定します。ここから先は、配布元ではなく**自分用のPrivateリポジトリ**を使います。配布元の組織への参加申請は必要ありません。

## 6. ChatGPTに話しかけて、ポートフォリオを作成・編集する

### 最初にルールを読んでもらう

接続できたら、同じ会話で次のように頼みます。新しい会話を始めたときも、自分用リポジトリのURLを添えてこの一文を送ってください。

> AGENTS.mdを読んで、記録を始める準備をしてください。

[AGENTS.md](../AGENTS.md)は、テンプレートに入っているAI用の指示書です。非公開の保存先と読み書きの確認、作成日・更新日の記入、本人の言葉の保持、mainへの直接保存、既存ファイルを壊さない更新、保存後の確認をルールにしています。毎回、長い指示を貼り付ける必要はありません。

指示書は、ファイルを置くだけで必ず読み込まれるものではありません。ChatGPTが指示書を読めて、記録を作成・更新できることを確認してから進めます。読み取りだけの場合は直接保存できません。

### ChatGPTで記録を作って保存する

初期設定が終わったら、実際のメモを伝えます。用紙やファイル名、日付の整理はChatGPTに任せられます。音声で伝える場合は、文字起こしされた本人の発言や日付を確認してください。

### 体験を伝える

次は**書き方を示す架空例**です。実際に依頼するときは、活動日とメモを自分の体験に置き換えてください。架空例のまま練習するときは、本人の実記録ではなくexamples/に保存するよう伝えます。

> 記録の案を作ってください。2026年9月26日の運動会でかけっこに参加し、本人が「走る前はどきどきした」と話しました。

例えば、保存先は `experiences/2026-09-26-sports-day.md` のようになります。保存先や文章案を確認し、直したいところがあれば普段の言葉で伝えます。

### 確認してGitHubに保存する

- 本人が言っていない感想が追加されていないか。
- 体験した日と、作成日・更新日が分かれているか。
- 元のメモが残り、保存先が自分用のPrivateになっているか。

本人の言葉・メモ・作成日・更新日を確認し、内容がよければ次のように依頼します。

> この内容で保存してください。

GitHubでリンク先を開き、mainのファイルと日付を確認できれば完了です。

この方法では、接続ツールがGitHub上のファイルを直接更新してコミットを作ります。パソコンでgit pushコマンドを打つ操作は不要です。結果は「mainに直接保存」となり、プルリクエストの作成・マージは行いません。

文章案が返っただけなら未保存です。「保存できなかった」と出た場合も完了とはせず、理由を確認します。

### あとから書き足すとき

例えば、本人から翌日の感想を聞いたら、ファイルを開いて手で入力する代わりに次のように頼めます。これも架空例です。

> 9月26日の運動会の記録に、2026年9月27日に本人が「また走りたい」と話したことを追記する案を見せてください。

案を確認したら、同じように「この内容で保存してください」と頼みます。

各用紙には作成日・更新日の欄があります。作成日はノートを書き始めた日、更新日は内容を最後に直した日で、体験した日とは分けます。詳しくは[日付の具体例](file-dates.md)を参照してください。

## 困ったとき

- **PluginsやGitHubが見つからない**: アプリの更新と、アカウントでの提供状況を確認します。「Apps（アプリ）」など別の接続画面が表示される場合も、名称だけで同じ機能だと判断せず、ファイル更新に対応しているか確認します。
- **読み取りしかできない**: この接続ではChatGPTから直接保存できません。書き込み対応のGitHubプラグインが利用可能か確認し、提供されていなければ本文の下書きまで行い、このページの「補足: 自分でファイルを編集するとき」を使います。
- **一覧にノートが出ない**: GitHubで許可したアカウント・リポジトリを確認します。URLを直接指定して読めるか試す方法もあります。
- **mainへの保存が拒否される**: 書き込み権限やブランチ保護が原因の場合があります。保護設定を自動で解除させず、拒否の理由を確認します。
- **ファイルが変わらない**: 保存先・ブランチ・コミット・保存後の再読み取り結果を確認します。
- **日付が入らない**: [日付のルール](file-dates.md)とAGENTS.mdを読み、修正するよう依頼します。

## 最小限で始める

最初は `experiences/` に一言の記録を残すだけで十分です。

例えば、科学館で見た紙の橋に興味が続いたら、ChatGPTに「紙の橋について、探究ノートの案を作って」と頼めます。活動日や実際に試したことを伝え、内容を確認してから保存します。

元の科学館の記録も開けるようにするには、本文に次のように書きます。これは、2026年9月28日の科学館の体験を保存したと仮定した架空例です。

```markdown
- きっかけの体験記録: [科学館での体験](../experiences/2026-09-28-science-museum.md)
```

角括弧の中の「科学館での体験」がリンクの表示名、丸括弧の中がファイルの場所です。実際に保存した名前に合わせて書き換えます。

用紙の空欄は無理に埋めず、不要な項目は省略できます。架空例は `examples/` に分離したままにします。

## ときどき手元にも保存する

自分用リポジトリのトップで **Code → Download ZIP** を選ぶと、現在のファイルをまとめてダウンロードできます。

例えば、月末にダウンロードしたZIPを、パソコンの自分で管理するフォルダに `学びのノート-2026-09-30.zip` のような日付入りの名前で保管すると、いつの控えかわかります。実際に保存した日付を使ってください。

このZIPには変更履歴全体や、外部ストレージに置いた写真・動画は含まれません。外部の原本は別途バックアップします。

公式手順: [テンプレートからリポジトリを作る](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template)

## 補足: 自分でファイルを編集するとき

AIが使えないときや、操作の意味を知りたいときの手順です。

<details>
<summary>GitHub画面で手動保存する手順と具体例を開く</summary>

ここでは、**2026年9月26日の運動会を記録する場合**を例にします。以下の内容はすべて架空です。実際に体験したこと・本人が言ったことに置き換えてください。

1. 自分用リポジトリで `templates` フォルダを開き、`quick-note.md` を選びます。**Raw**（文章の元データを表示）などから本文をコピーします。
2. リポジトリのトップに戻り、**Add file → Create new file**（ファイルを追加 → 新しいファイルを作成）を選びます。
3. ファイル名の欄に、例えば **`experiences/2026-09-26-sports-day.md`** と入力します。基本の形は `experiences/YYYY-MM-DD-theme.md` です。`YYYY-MM-DD` を実際の日付、`theme` を短いテーマに置き換えます。テーマは `sports-day` のように英語かローマ字にし、「運動会」のような日本語の題名は本文の見出しに書きます。日本語のファイル名も使えますが、MacとWindowsで同じ名前として扱われないことがあるため勧めません。
4. 本文の入力欄に、コピーした用紙を貼り付け、書けるところを埋めます。下の「本文の記入例」を参考にしてください。
5. **Preview**（プレビュー）で内容を見直し、**Commit changes**（変更を保存）を押します。保存内容の説明欄が出たら、例えば `運動会の記録を追加` と入力し、確認画面の **Commit changes** で保存します。

保存後に `experiences` フォルダを開き、`2026-09-26-sports-day.md` が見つかれば完了です。

### ファイル名の読み方と具体例

`experiences/` は「体験を入れるフォルダ」、`2026-09-26` は「体験した日」、`sports-day` は「内容がわかる短い名前」です。最後の **`.md` はそのまま残します**。文章を保存するファイルの種類を表しています。

| 記録したいこと（架空例） | ファイル名の欄に入力する文字 |
| --- | --- |
| 2026年9月26日の運動会 | `experiences/2026-09-26-sports-day.md` |
| 2026年9月27日に読んだ本 | `experiences/2026-09-27-reading.md` |
| 2026年9月28日の科学館 | `experiences/2026-09-28-science-museum.md` |
| 同じ日の運動会について、別の記録をもう1件作る | `experiences/2026-09-26-sports-day-02.md` |
| 日付を覚えていない科学館の体験 | `experiences/date-unknown-science-museum.md` |

`YYYY-MM-DD` は「年4桁-月2桁-日2桁」という意味です。例えば9月6日なら `2026-09-06` とします。日付がわからない場合は推測せず、本文にも「未確認」と書きます。

### 本文の記入例（すべて架空）

次のように、一言ずつでも十分です。実際には聞いていない発言を、そのままコピーして本人の言葉にしないでください。

```markdown
# 運動会の記録

- 作成日: 2026-09-26
- 更新日: 2026-09-26
- いつ: 2026-09-26
- 書いた人: 保護者の代筆
- やったこと・見たもの: 運動会のかけっこに参加した。
- 本人のことば: 「走る前はどきどきした」
- つぎに気になること: 未確認
- 保護者の観察: 走り終わったあと、友だちの競技を見ていた。
- メモ: かけっこに参加。「走る前はどきどきした」と話した。終わったあと友だちの競技を見ていた。
```

本人の言葉を正確に覚えていなければ、例えば `保護者による要約: 走る前に緊張したと話していた。` のように書きます。聞いていないこと・わからないことは、空欄か「未確認」で大丈夫です。

### あとから書き足す場合

例えば、翌日に本人が「また走りたい」と話したら、保存済みの `2026-09-26-sports-day.md` を開き、編集ボタンから次のように追記して保存します。

```markdown
## 2026-09-27の追記（架空例）
- 本人のことば: 「また走りたい」
```

元の記録は残し、あとから聞いたことは追記した日付を付けます。この例では、冒頭の作成日は2026-09-26のまま、更新日を2026-09-27に変更します。保存内容の説明は、例えば `運動会の翌日の感想を追記` とします。

コミットとは、その時点の内容を履歴として保存することです。`運動会の記録を追加` や `運動会の翌日の感想を追記` という説明があれば、後日何を変えたのかを見返しやすくなります。

</details>
