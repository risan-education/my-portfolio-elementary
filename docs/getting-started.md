# はじめ方（保護者向け）

- 作成日: 2026-09-25
- 更新日: 2026-09-26

## GitHubを初めて使う方へ

GitHubは、文章や写真を変更履歴とともに保存できるサービスです。この教材では、保護者が管理する学びのノート置き場として使います。

**[「GitHubって何？ 登録とログインのしかた」を開く](github-basics.md)**

Googleアカウントを持っていない方の作成手順から、GoogleでのGitHub登録・次回のログインまで説明しています。初めての方は、先にそのページで登録とログインを済ませてください。

## 自分用の場所を作る

1. 保護者自身のGitHubアカウントで[ログイン](https://github.com/login)します。Googleで登録した方は **Continue with Google** を選びます。
2. [配布元のトップページ](https://github.com/risan-education/my-portfolio-elementary)で **Use this template → Create a new repository** を選びます。「このひな形から、自分用の保存場所を作る」という操作です。
3. **Owner（所有者）**には保護者のアカウント、**Repository name（保存場所の名前）**には、例えば `family-learning-notes` と入力します。名前に子どもの本名や学校名を入れる必要はありません。
4. **Private（非公開）**を選びます。「Include all branches」はチェックせずに進みます。
5. **Create repository from template** で作成し、リポジトリ名のそばに **Private** と表示されることを確認します。

例えば、保護者のユーザー名が `learning-parent`、保存場所の名前が `family-learning-notes` なら、ページ上部には `learning-parent / family-learning-notes` と表示されます。これは説明用の架空の名前です。実際には自分のユーザー名が表示されます。

この**自分用のページ**をブラウザーのお気に入りに保存すると、次回から開きやすくなります。

「Use this template」が表示されない場合は、ログイン済みか、配布元のトップページを開いているかを確認してください。公開リポジトリに実記録を書かず、自分用のPrivateリポジトリを作ってから記録を始めます。

GitHubの利用は原則13歳以上です。小学生本人のアカウント作成や保護者のログイン情報の共有を前提にせず、保護者が自分のアカウントを操作します。
[GitHubの利用規約](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)を確認してください。

## ChatGPTかCopilotを準備する

この教材は、**保護者がAIに体験を伝え、AIがファイルを作り、内容を確認して保存する**使い方を基本にします。どちらか一方で始められます。

| 使うもの | 月額の目安 | 最初にすること | 毎回の流れ |
| --- | --- | --- | --- |
| ChatGPT PlusのCodex | 1か月 約3,000円 | [GitHubへの接続と環境作成](chatgpt-plus-setup.md) | 依頼 → 変更内容を確認 → GitHubへ取り込む |
| GitHub Copilot Pro | 1か月 約1,500円 | [VS Codeと自分用ノートの設定](copilot-setup.md) | 依頼 → 変更内容を確認 → GitHubへ送信 |

金額は概算です。為替・税・契約方法などによって変わるため、実際の請求額は契約画面で確認してください。Copilotの金額は有料のProプランの目安です。

通常のチャットで文章が返ってきただけでは、ファイルが保存されたとは限りません。上の手順で、**自分用のPrivateリポジトリを編集できる環境**を用意します。Copilotは無料枠でも試せます。学生向けの条件は[中学生とCopilotの無料利用](copilot-students.md)にまとめています。

## AIに話しかけて1件作る

初期設定が終わったら、毎回手で用紙をコピーする必要はありません。実際の原メモを入力し、ファイルの整理はAIに頼みます。ここでいう「話しかける」は、まずチャット欄への日本語入力です。音声を使う場合も、文字起こしされた本人の発言や日付を確認して送信してください。

### 最初の1回はルールを確認する

> AGENTS.mdを読んでください。保存先が私のPrivateリポジトリであることを確認し、作成日・更新日と本人の言葉をどう扱うか説明してください。まだファイルを編集しないでください。

### 体験を伝える

次は**書き方を示す架空例**です。実際に依頼するときは、活動日と原メモを自分の体験に置き換えてください。架空例のまま練習するときは、本人の実記録ではなくexamples/に保存するよう伝えます。

> AGENTS.mdに従って、体験を1件記録してください。
>
> 活動日: 2026-09-26
>
> 原メモ: 運動会のかけっこに参加した。本人が「走る前はどきどきした」と話した。
>
> templates/quick-note.mdを参考に、experiences/2026-09-26-運動会.mdを作ってください。ファイルがすでにある場合は上書きせず確認してください。作成日・更新日は日本時間の実行日を確認して入れ、活動日とは分けてください。原メモにない発言や出来事は足さず、未確認の項目は未確認にしてください。編集後に保存先と変更内容を見せてください。

ファイル名が思いつかないときは「日付と内容から、短い日本語のファイル名を提案して作ってください」でも構いません。AIに必要な情報が足りなければ、聞かれたことに答えます。

### 確認してGitHubに保存する

- 本人が言っていない感想が追加されていないか。
- 体験した日と、作成日・更新日が分かれているか。
- 元のメモが残り、保存先が自分用のPrivateになっているか。

確認後は[Copilotの保存手順](copilot-setup.md)または[Codexの反映手順](chatgpt-plus-setup.md)でGitHubに反映します。最後にGitHubで新しいファイルを開ければ完了です。

### あとから書き足すとき

例えば、本人から翌日の感想を聞いたら、ファイルを開いて手で入力する代わりに次のように頼めます。これも架空例です。

> experiences/2026-09-26-運動会.mdに追記してください。2026-09-27に本人が「また走りたい」と話しました。元の記録と作成日は保持し、追記の日付を残してください。更新日は今回編集する日です。変更内容を見せてください。

## 補足: 自分でファイルを編集するとき

AIが使えないときや、操作の意味を知りたいときの手順です。普段の記録は、上のAIへの依頼から始めて構いません。



ここでは、**2026年9月26日の運動会を記録する場合**を例にします。以下の内容はすべて架空です。実際に体験したこと・本人が言ったことに置き換えてください。

1. 自分用リポジトリで `templates` フォルダを開き、`quick-note.md` を選びます。**Raw**（文章の元データを表示）などから本文をコピーします。
2. リポジトリのトップに戻り、**Add file → Create new file**（ファイルを追加 → 新しいファイルを作成）を選びます。
3. ファイル名の欄に、例えば **`experiences/2026-09-26-運動会.md`** と入力します。基本の形は `experiences/YYYY-MM-DD-theme.md` です。`YYYY-MM-DD` を実際の日付、`theme` を短いテーマに置き換えます。テーマは「運動会」のように日本語でも大丈夫です。
4. 本文の入力欄に、コピーした用紙を貼り付け、書けるところを埋めます。下の「本文の記入例」を参考にしてください。
5. **Preview**（プレビュー）で内容を見直し、**Commit changes**（変更を保存）を押します。保存内容の説明欄が出たら、例えば `運動会の記録を追加` と入力し、確認画面の **Commit changes** で保存します。

保存後に `experiences` フォルダを開き、`2026-09-26-運動会.md` が見つかれば完了です。

### ファイル名の読み方と具体例

`experiences/` は「体験を入れるフォルダ」、`2026-09-26` は「体験した日」、`運動会` は「内容がわかる短い名前」です。最後の **`.md` はそのまま残します**。文章を保存するファイルの種類を表しています。

| 記録したいこと（架空例） | ファイル名の欄に入力する文字 |
| --- | --- |
| 2026年9月26日の運動会 | `experiences/2026-09-26-運動会.md` |
| 2026年9月27日に読んだ本 | `experiences/2026-09-27-読書.md` |
| 2026年9月28日の科学館 | `experiences/2026-09-28-科学館.md` |
| 同じ日の運動会について、別の記録をもう1件作る | `experiences/2026-09-26-運動会-02.md` |
| 日付を覚えていない科学館の体験 | `experiences/date-unknown-科学館.md` |

`YYYY-MM-DD` は「年4桁-月2桁-日2桁」という意味です。例えば9月6日なら `2026-09-06` とします。日付がわからない場合は推測せず、本文にも「未確認」と書きます。

### 本文の記入例（すべて架空）

次のように、一言ずつでも十分です。実際には聞いていない発言を、そのままコピーして本人の言葉にしないでください。

```markdown
# 運動会の記録

- 作成日: 2026-09-26
- 更新日: 2026-09-26
- いつ: 2026-09-26
- 書いた人: 保護者の代筆
- やったこと・見たもの: 運動会のかけっこに参加した。
- 本人のことば: 「走る前はどきどきした」
- つぎに気になること: 未確認
- 保護者の観察: 走り終わったあと、友だちの競技を見ていた。
- 原メモ: かけっこに参加。「走る前はどきどきした」と話した。終わったあと友だちの競技を見ていた。
```

本人の言葉を正確に覚えていなければ、例えば `保護者による要約: 走る前に緊張したと話していた。` のように書きます。聞いていないこと・わからないことは、空欄か「未確認」で大丈夫です。

### あとから書き足す場合

例えば、翌日に本人が「また走りたい」と話したら、保存済みの `2026-09-26-運動会.md` を開き、編集ボタンから次のように追記して保存します。

```markdown
## 2026-09-27の追記（架空例）
- 本人のことば: 「また走りたい」
```

元の記録は残し、あとから聞いたことは追記した日付を付けます。この例では、冒頭の作成日は2026-09-26のまま、更新日を2026-09-27に変更します。保存内容の説明は、例えば `運動会の翌日の感想を追記` とします。

コミットとは、その時点の内容を履歴として保存することです。`運動会の記録を追加` や `運動会の翌日の感想を追記` という説明があれば、後日何を変えたのかを見返しやすくなります。

## 最小限で始める

最初は `experiences/` に一言の記録を残すだけで十分です。

例えば、科学館で見た紙の橋に興味が続いたら、[探究ノート](../templates/inquiry.md)の本文をコピーし、`projects/2026-10-01-紙の橋.md` のような名前で新しいファイルを作ります。日付とテーマは実際のものに置き換えます。

元の科学館の記録も開けるようにするには、本文に次のように書きます。これは、上の架空例のファイルを作った場合の記入例です。

```markdown
- きっかけの体験記録: [科学館での体験](../experiences/2026-09-28-科学館.md)
```

角括弧の中の「科学館での体験」がリンクの表示名、丸括弧の中がファイルの場所です。実際に保存した名前に合わせて書き換えます。

用紙の空欄は無理に埋めず、不要な項目は省略できます。架空例は `examples/` に分離したままにします。

## ときどき手元にも保存する

自分用リポジトリのトップで **Code → Download ZIP** を選ぶと、現在のファイルをまとめてダウンロードできます。

例えば、月末にダウンロードしたZIPを、パソコンの自分で管理するフォルダに `学びのノート-2026-09-30.zip` のような日付入りの名前で保管すると、いつの控えかわかります。実際に保存した日付を使ってください。

このZIPには変更履歴全体や、外部ストレージに置いた写真・動画は含まれません。外部の原本は別途バックアップします。

公式手順: [テンプレートからリポジトリを作る](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template)

## AIにファイルの作成・編集を頼む場合

[Copilotの初期設定](copilot-setup.md)または[ChatGPT Plusの初期設定](chatgpt-plus-setup.md)から始めます。各用紙には作成日・更新日の欄があり、AI用指示書にも日付ルールを設定しています。
作成日はノートを書き始めた日、更新日は内容を最後に直した日です。体験した日とは分けます。詳しくは[日付の具体例](file-dates.md)を参照してください。
