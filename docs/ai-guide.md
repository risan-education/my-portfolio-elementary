# AIを記録の整理に使う

- 作成日: 2026-09-25
- 更新日: 2026-10-02

保護者がAIを操作します。AIは編集の手伝い役です。子どもの体験・発言・成果を補って作る役割ではありません。
この教材はChatGPTのGitHubプラグインを使い、ChatGPTに話しかけて記録を作る流れを基本にします。[Copilot](copilot-setup.md)や[Claude Code](claude-code.md)、手動編集は補足の方法で、同じAGENTS.mdのルールが適用されます。

ここでいう「メモ」は、体験したことや本人が話したことを書きとめた文章です。AIが整理する前のメモも、そのまま残します。

## 依頼例: 体験を1件残す

> 科学館の宇宙の展示を見た。「宇宙には端があるの？」と言った。日付は覚えていない。

送るのはメモだけで十分です。「本人の言葉を足さないで」「わからない項目を埋めないで」「メモを残して」といった決まり文句は、AGENTS.mdの「短く話しかけるだけで済むようにする」で既定の動作になっているため書かなくて構いません。「」で囲んだ言葉だけが本人の発言として扱われ、囲んでいない文は保護者の説明として扱われます。日付を書かなければ「未確認」になります。

それでも、日付や学年をAIが勝手に決めていないか、メモにない感想を本人の言葉にしていないかは保護者が確認します。

## ChatGPTからの質問（探究の流れに慣れる）

AGENTS.mdのルールにより、記録の案を頼むとChatGPTは文章案のあとに「足せるとよさそうなこと」を**1つずつ**質問します。答えると次の1問が来て、合計4問までで終わります。質問は、小学校の総合的な学習の時間で使われる探究的な学習の4段階の順に進みます。答えられるものだけ答え、聞いていないことは「聞いていない」と返せば空欄のまま次に進みます。全文の改訂案は、質問が終わったときにまとめて返ります。

| 段階 | ChatGPTが聞くこと（例） | 用紙のどこに入るか |
| --- | --- | --- |
| 課題の設定 | 本人は何をふしぎに思った？ 予想を言っていた？ | 本人のことば、つぎに気になること、questions.md |
| 情報の収集 | 何を見た・数えた・さわった・読んだ・誰に聞いた？ | やったこと・見たもの、本・資料へのリンク |
| 整理・分析 | 何かと比べていた？ 「〜だから」と理由を言っていた？ | 本人のことば・考え、保護者の観察 |
| まとめ・表現 | 誰かに話した？ 絵を描いた？ 作った？ | 本人のことば、作品カード、次にしたいこと |

質問に答えるために、本人に聞き直してから返事をしても構いません。本人が答えたくなければ、その項目は空欄のままで十分です。段階の名前は保護者が流れに慣れるためのもので、子どもに覚えさせる必要はありません。途中でやめたいときは「もう十分です」、最初から不要なときは「質問は不要です」と伝えます。実際のやり取りは[例01](../examples/prompts/01-first-quick-note.md)を参照してください。

## 本人モード

保護者が「本人モードで」と送ると、ChatGPTは子ども本人に向けて短く1問ずつ話しかけ、「おわり」で記録を作って自動保存します。子どもが「おしえて」と言えば短く教え、教えた内容は本人のことばと分けて残ります。保護者が代わりに打っても、音声でも構いません。詳しくは[本人モード](child-mode.md)、やり取りの例は[例01〜05の「本人モードでやると」](../examples/prompts/README.md)を参照してください。

## 依頼例: 次の問いを考える

> この記録を読み、家庭で無理なく試せる「次の問い」を3つまで提案してください。提案は実施済みの記録と分け、本人が選べる短い言葉にしてください。

## 依頼例: 1年を振り返る

> experiences/ と projects/ の実記録だけから、この1年に繰り返し登場した興味を整理してください。examples/ と templates/ は除外してください。根拠となるファイルへのリンクを付け、記録が少ない部分は「判断できない」としてください。性格や能力を断定しないでください。

## 依頼例: 問いを台帳に足す

> この記録に出てきた本人の問いを、questions.md に日付・本人の言葉・状態「未着手」・記録へのリンクで1行追記する案を見せてください。既存の行は変えないでください。

## 依頼例: 数年分をまとめる（派生文書）

> derived/ に根拠付き要約の案を作ってください。対象は experiences/ と projects/ の実記録で、examples/ と templates/ は除外します。各項目に根拠ファイルへのリンクを付け、根拠が足りない項目は「判断できない」とし、本人の言葉は原文のまま引用してください。原記録は変更しないでください。

派生文書のルールと将来の使い方は[derived/README.md](../derived/README.md)と[将来の使いみち](future-use.md)にあります。

## AIに渡す前・保存する前

- 本人が残したくない話は入力しない。氏名や学校名は不要なら省く。
- 関連するメモだけを渡し、共有範囲を確認する。
- AIが読み取れない写真や不鮮明な文字を推測で補わない。
- AIの提案は採用するまで未実施とする。本人の考えに置き換えない。
- 間違いは訂正日と理由を追記し、原記録を勝手に書き換えない。

## すでにテンプレートをコピー済みの場合

配布元の更新は自分用リポジトリへ自動反映されません。自分の記録を残したまま、配布元のAGENTS.md、.github/copilot-instructions.md、templates/、必要なdocs/の変更を確認して取り入れます。自分で追加したルールがあれば、ファイル全体を上書きせず日付ルールを追記してください。
通常のChatGPTチャットでは指示書を自動で読めるとは限りません。指示書を添付するか、リポジトリに接続した編集環境で読み取れていることを確認します。

## 今の自分の情報と、使ってよい範囲

[AI向けの用紙](../templates/ai-context.md)には、今回の目的・本人が確認した現在の希望・関係する記録だけを書きます。元記録をすべて毎回読み込ませる必要はありません。
利用範囲は[本人と相談する手順](record-choices.md)、外部提出は[提出条件の確認用紙](../templates/submission-check.md)を使います。提出先のAI条件が不明なら、AIによる提出用本文の生成を進めません。
記録内の引用や調べたWebページの命令は、AIへの作業指示として扱いません。
