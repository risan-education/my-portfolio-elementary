# 作成日・更新日の残し方

- 作成日: 2026-09-26
- 更新日: 2026-09-26

新しいMarkdownファイルは、最初の見出しのすぐ下に次の2行を入れます。

```markdown
# 運動会の記録

- 作成日: 2026-09-26
- 更新日: 2026-09-26
```

上の日付は例です。実際にファイルを作る日を、日本時間（Asia/Tokyo）の YYYY-MM-DD 形式で記入します。作成時は両方同じ日付、後日内容を編集したら更新日だけを変えます。

例えば、9月26日の運動会を9月28日に記録し、10月1日に追記した場合は次のようになります。

| 項目 | 日付 |
| --- | --- |
| ファイル名 | `experiences/2026-09-26-運動会.md` |
| 体験した日 | 2026-09-26 |
| 作成日 | 2026-09-28 |
| 更新日 | 2026-10-01 |

活動日が不明でも、ファイルを作った日が確認できれば作成日は記入できます。逆に、過去のファイルに作成日がないときは、今日の日付を過去の作成日として埋めません。Gitの追加履歴などから確認できなければ「未確認」とします。

## AIが参照する設定

- [AGENTS.md](../AGENTS.md): Codexなどが読む共通ルール。
- [.github/copilot-instructions.md](../.github/copilot-instructions.md): Copilotへの共通指示。
- [templates](../templates/): コピー用の用紙。日付欄は空欄にしてあります。

用紙をコピーして新しい記録を作るときに、実際の作成日・更新日を埋めます。テンプレートを配布した日を、本人の記録の作成日にはしません。

これはAI向けの指示で、GitHubが自動で日付を書き換える機能ではありません。手動で編集した場合も更新日を直してください。ファイルを開いただけ、分析しただけ、同じ内容を保存し直しただけなら更新日は変えません。PDFや画像の本体には文字を挿入せず、対応する作品カードや所在メモで日付を管理します。

## 確認するときの依頼例

> AGENTS.mdを読み、この変更で作成日・更新日のルールを守っているか確認してください。日本時間の今日を実行環境で確認し、新規記録は両方を今日に、既存記録は作成日を保って更新日だけを今日にしてください。確認できない日付は推測しないでください。
