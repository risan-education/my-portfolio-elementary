# save-prompt: 依頼と結果を記録して main に保存する

- 作成日: 2026-09-27
- 更新日: 2026-09-27

このリポジトリの管理者は、AI に出した依頼（プロンプト）とその結果を `docs/prompt/` にためて、あとから「なぜこの変更をしたか」をたどれるようにしています。記録は依頼の原文を保つことに価値があるので、言い換えや要約に置き換えないでください。結果の側は、変更したファイルとコミットが分かれば十分です。

## 手順

1. **日付を確認する。** 日本時間（Asia/Tokyo）の今日を `TZ=Asia/Tokyo date +%F` などで確認し、ファイル名用の `YYMMDD`（西暦下2桁・月・日）と本文用の `YYYY-MM-DD` を用意する。確認できなければ推測せず「未確認」と書く。
2. **対象の依頼を決める。** 前回の `/save-prompt` 以降（初回なら会話の最初から）に利用者が送った依頼を対象にする。`/save-prompt` の指示そのものは対象から外し、同じメッセージに他の依頼文があればそれは含める。話題が明らかに別の依頼が複数あるときは、連番を分けて1依頼1ファイルにしてよい。
3. **ファイル名を決める。** `docs/prompt/YYMMDD-NN-title.md`。`NN` はその日の連番で `01` から。既存の `docs/prompt/` を `ls` して同じ日付の最大番号の次を使い、既存ファイルを上書きしない。`title` は英語かローマ字の短い語（例: `relicense-cc-by`, `push-to-main`）。日本語の題名は本文の見出しに書く。
4. **記録を書く。** 下の「記録の形式」に従う。依頼本文はフェンス（```）で囲んで原文のまま貼る。添付ファイルがあればファイル名と要旨を書き、本文全体は貼らない。パスワード・トークン・本名などが含まれていれば伏せ、その旨を書く。
5. **すべての変更を保存する。** `git add -A` で今回の記録を含む未コミットの変更をすべてステージし、`docs: save prompt YYMMDD-NN-title` のようなメッセージでコミットする。`git fetch origin main` して遅れていれば `git rebase origin/main`（競合は両方の内容を残して解消）し、`git push -u origin main` する。作業ブランチや pull request は作らない。強制 push はしない。
6. **確認して報告する。** `git ls-remote --heads origin main` か GitHub 上の `main` を読み直し、コミットが載っていることを確かめる。記録ファイルのパス、コミットの短縮ハッシュ、push 結果を短く報告する。push できなかったときは「保存済み」と言わず、理由と未反映の状態を伝える。

## 記録の形式

```markdown
# 依頼の記録: （日本語の題名）

- 作成日: YYYY-MM-DD
- 更新日: YYYY-MM-DD
- 依頼日: YYYY-MM-DD
- 依頼者: 利用者
- 使ったAI: Claude Code（または ChatGPT など）
- 添付: なし（あればファイル名と要旨）

## プロンプト本文

（利用者が送った文章を、フェンスで囲んで原文のまま。複数あれば送った順に）

## 結果の要約

- 何をしたか（数行）
- 変更・追加・削除したファイル（パスの一覧）
- コミット: 短縮ハッシュ（この記録自体を含むコミットは「この記録のコミット」と書く）
- 未実施・未確認・利用者に確認が必要な事項

## 関連

- 関連する docs/ や CHANGELOG の項目へのリンク（あれば）
```

## 気をつけること

- `scripts/check-docs.ps1` は、すべての Markdown に「- 作成日:」「- 更新日:」の行がちょうど1つずつあることを求める。依頼本文に同じ行が含まれていても、フェンスの中なら数えられないので、必ずフェンスで囲む。
- `docs/prompt/` は配布元（管理者）用の作業記録であり、子どもの実記録の置き場ではない。利用者の家庭のリポジトリに実記録の依頼が混ざっていたら、個人情報を伏せる。
- 記録の作成日は「ファイルを作った日」。依頼日と一致しなくてもよい。
- 既存の記録は書き換えず、訂正は日付付きで追記する。
