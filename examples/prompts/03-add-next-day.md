# 例03: 翌日に聞いた一言を、前の記録に書き足す（架空）

- 作成日: 2026-10-01
- 更新日: 2026-10-01

## こんなとき

[例01](01-first-quick-note.md)でダンゴムシの記録を保存した翌日、同じ公園でまたダンゴムシを見つけて、子どもが新しいことを言った。新しいファイルを作るほどではないので、前の記録に追記したい。元の文章は変えず、日付付きで足します。

追記の依頼では、ChatGPTの質問は新しい発言に関するもの1つだけです。

## 1往復目

**保護者 → ChatGPT**（コピーして、自分の内容に置き換える）

```text
10月3日のダンゴムシの記録（experiences/261003-dangomushi.md）に追記する案を見せてください。
2026年10月4日、同じ公園で本人が「今日もいた」「石の下にいた。くらいところがすきなのかな」と言いました。
元の文章は変えず、追記の形にしてください。更新日は10月4日にしてください。
```

**ChatGPT → 保護者**（架空例）

> `experiences/261003-dangomushi.md` の末尾に、次の見出しを追記します。元の本文は変更しません。冒頭の「作成日」は 2026-10-03 のまま、「更新日」だけ 2026-10-04 に変えます。

```markdown
## 2026-10-04の追記
- やったこと・見たもの: 同じ公園でまたダンゴムシを見つけた。
- 本人のことば: 「今日もいた」「石の下にいた。くらいところがすきなのかな」
- 保護者の観察: 未確認
```

> 本人の「くらいところがすきなのかな」は予想のように聞こえますが、本人の発言としてそのまま引用しました。
>
> **質問1（情報の収集）**: 「くらいところがすきなのかな」と言ったあと、本人が何か確かめようとしていましたか（別の石を持ち上げて見る、明るい場所を探す、など）。していなければ「していない」で大丈夫です。

## 2往復目

**保護者 → ChatGPT**

```text
石を3つくらい持ち上げて見ていました。2つ目の石の下にいました。
```

**ChatGPT → 保護者**

> 反映しました。追記の案は次のとおりです。質問はここまでです。

```markdown
## 2026-10-04の追記
- やったこと・見たもの: 同じ公園でまたダンゴムシを見つけた。石を3つくらい持ち上げて見て、2つ目の石の下にいた。
- 本人のことば: 「今日もいた」「石の下にいた。くらいところがすきなのかな」
- 保護者の観察: 「くらいところがすきなのかな」と言ったあと、自分で石を持ち上げて確かめていた。
- メモ: （回答1）石を3つくらい持ち上げて見ていた。2つ目の石の下にいた。
```

> `questions.md` の既存の行（「なんでまるくなるの？」）は変えません。新しい問いとして足す場合は次の案があります。

```text
| 2026-10-04 | 「くらいところがすきなのかな」 | 未着手 | [ダンゴムシ](experiences/261003-dangomushi.md) | 本人の予想として発言。石を3つ持ち上げて確かめていた |
```

## 確認して保存する

- 元の記録の本文（10月3日の部分）が一文字も変わっていないか。
- 作成日が 2026-10-03 のまま、更新日だけが 2026-10-04 になっているか。
- 追記の見出しに日付が付いているか。

```text
この内容で保存してください。questions.md の追記は本人に聞いてから決めるので、今回は記録だけお願いします。
```

## ポイント

- 追記は「あとから聞いたこと」を、いつ聞いたか分かる形で足す方法です。元の記録を書き直して、きれいな一つの文章にはしません。
- 「くらいところがすきなのかな」のような本人の予想は、大人が正解に直さず、そのまま残します。あとで本人が調べたときに「前はこう思っていた」と比べられます。
- 「石を持ち上げて確かめた」は、本人が自分で情報を集めた場面です。質問1つでこうした場面が記録に残ります。
- 作成日はファイルを作った日なので変わりません。更新日だけが動きます。詳しくは[作成日・更新日のルール](../../docs/file-dates.md)。
