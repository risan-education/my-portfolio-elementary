# 例03: 翌日に聞いた一言を、前の記録に書き足す（架空）

- 作成日: 2026-10-01
- 更新日: 2026-10-02

このページの発言・活動・日付はすべて架空です。2026-10-04に記録を追記する設定で、活動日と編集日が同じ場合を示しています。

## こんなとき

[例01](01-first-quick-note.md)でダンゴムシの記録を保存した翌日、同じ公園でまたダンゴムシを見つけて、子どもが新しいことを言った。新しいファイルを作るほどではないので、前の記録に追記したい。元の文章は変えず、日付付きで足します。

## まず見る短い例

**送るメモ**（実際の内容に置き換える）

> 10月3日のダンゴムシの記録に追記。10月4日、同じ公園で「今日もいた」「石の下にいた。くらいところがすきなのかな」と言った。

**できあがる日記**（最初のメモだけで作る案・既存の日記に足す文）

10月4日: 同じ公園でまたダンゴムシを見つけた。「今日もいた」「石の下にいた。くらいところがすきなのかな」。

（本人のことばと記録から AI が構成）

**保存先**: `experiences/261003-dangomushi.md`。文章案を読み直し、よければ次を送ります。質問に答えず、この時点で保存しても構いません。

```text
この内容で保存してください。questions.md の追記は本人に聞いてから決めるので、今回は記録だけお願いします。
```

保存後はmainのファイルを開いて確認します。index.md は既存行の最終更新を直します。以下の詳しい例では、追加の回答がどこに反映されるかを示します。

```markdown
## 入力メモ（原文）

### 最初の入力

> 10月3日のダンゴムシの記録に追記。10月4日、同じ公園で「今日もいた」「石の下にいた。くらいところがすきなのかな」と言った。
```

> 本人の「くらいところがすきなのかな」は予想のように聞こえますが、本人の発言としてそのまま引用しました。
>
> **質問1（情報の収集）**: 「くらいところがすきなのかな」と言ったあと、本人が何か確かめようとしていましたか（別の石を持ち上げて見る、明るい場所を探す、など）。していなければ「していない」で大丈夫です。

```markdown
### 最初の入力

> 10月3日のダンゴムシの記録に追記。10月4日、同じ公園で「今日もいた」「石の下にいた。くらいところがすきなのかな」と言った。
```

```text
| 2026-10-04 | 「くらいところがすきなのかな」 | 未着手 | [ダンゴムシ](experiences/261003-dangomushi.md) | 本人の予想として発言。石を3つくらい持ち上げて見ていた |
```

## 確認して保存する

- 元の記録の本文（10月3日の部分）と、日記の10月3日の文が一文字も変わっていないか。日記には日付付きの行が足されるだけか。
- 作成日が 2026-10-03 のまま、更新日だけが 2026-10-04 になっているか。
- 追記の見出しに日付が付いているか。

```text
この内容で保存してください。questions.md の追記は本人に聞いてから決めるので、今回は記録だけお願いします。
```

## ポイント

- 「◯◯の記録に追記」と記録の名前を言えば、ChatGPTがファイルを探して追記の形にします。「元の文章は変えないで」「更新日だけ変えて」は言わなくて大丈夫です。
- 追記は「あとから聞いたこと」を、いつ聞いたか分かる形で足す方法です。元の記録を書き直して、きれいな一つの文章にはしません。
- 「くらいところがすきなのかな」のような本人の予想は、大人が正解に直さず、そのまま残します。あとで本人が調べたときに「前はこう思っていた」と比べられます。
- 「石を持ち上げて確かめた」は、本人が情報を集めた場面として残せます。質問1つでこうした場面が記録に残ります。
- 作成日はファイルを作った日なので変わりません。更新日だけが動きます。詳しくは[作成日・更新日のルール](../../docs/file-dates.md)。

